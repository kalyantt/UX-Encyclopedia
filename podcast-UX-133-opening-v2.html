Metadata, Taxonomy, Ontology, and Folksonomy

This recording is an editorial draft adapted from the revised lesson. It has not completed the final dialogue and audio review.

Before we begin

Host: Metadata, Taxonomy, Ontology, and Folksonomy.

Guide: Metadata is data that describes content: author, date, status, topic, audience, location, relationship, and more. A taxonomy is a controlled classification system. An ontology adds more explicit definitions and relationships between concepts. A folksonomy emerges from user-created tags. Each balances control, flexibility, maintenance cost, and discoverability.

Why it happens

Host: Why does that happen?

Guide: Choose structure proportionate to the task. Controlled fields make filtering and governance reliable; user tags can expose real language and emergent categories. A useful system documents definitions, owners, allowed values, and how changes are made. Without this, two teams can use the same label to mean different things and silently break retrieval.

Choose semantic machinery by the decisions it must support

Guide: Metadata records properties of an object. A taxonomy controls categories and their broader, narrower, or related structure. An ontology explicitly models entities, relationships, constraints, and sometimes inferential rules. A folksonomy captures participant-created tags.

Guide: More structure can improve retrieval and interoperability, but also increases governance and the harm caused by a wrong definition.

Automated enrichment remains a suggestion with confidence and review history.

Transfer example: research repository

Host: What changes when we look at transfer example: research repository?

Guide: Free tags reveal how researchers describe studies, while controlled audience, method, consent, region, and date enable reliable reuse. Treating tags as authority creates synonym drift; forbidding them loses emergent language. A governed mapping preserves both functions.

Choose the semantic layer required

Host: What changes when we look at choose the semantic layer required?

Guide: Metadata describes an object through fields such as type, date, owner, audience, status, and rights. A taxonomy provides controlled categories and hierarchical or associative relationships. An ontology expresses richer entities, properties, and rules. A folksonomy captures participant-created tags and emergent language.

Guide: Use the least complex layer that supports the decisions and retrieval required.

Guide: Define provenance, value constraints, cardinality, ownership, and lifecycle. Controlled structures improve consistency but require governance; user tags improve flexibility but create synonym, ambiguity, spam, and moderation needs. Map useful folksonomy terms into controlled concepts without erasing community language.

Guide: Test authoring burden and retrieval benefit. Missing or unreliable metadata can make facets and personalisation misleading. Automate suggestions where they remain reviewable, and audit drift, unused fields, category imbalance, and orphan concepts.

Guide: Semantics distribute power: categories determine what is visible, comparable, and reportable. Include affected perspectives when classification carries social or consequential meaning.

Govern semantic change as product change

Host: What changes when we look at govern semantic change as product change?

Guide: Vocabulary changes are tested against search, navigation, analytics, APIs, content, staff workflows, and historical records. Merging two clinic categories may simplify browsing but destroy a distinction required for referral routing. A folksonomy can reveal patient language and emerging concepts, yet it requires moderation and mapping before becoming authoritative domain data.

The harder decision

Host: Where does the harder design decision appear?

Guide: Metadata is an organisational agreement disguised as a technical field. If no one owns the vocabulary or update rules, a taxonomy becomes stale faster than the interface around it.

Look more closely

Host: What should we look at more closely?

Guide: Model the information before implementing filters. Identify entities, attributes, relationships, valid values, hierarchy, lifecycle, source of truth, and permissions. Then decide which terms must be controlled for reliable retrieval and reporting, which can remain flexible, and how user language will be captured without corrupting the canonical structure.

Guide: Metadata quality directly affects search, navigation, recommendations, analytics, and AI retrieval.

Guide: Failure modes to watch

Guide: Field without definition: teams enter the same metadata label with incompatible meanings. Taxonomy without owner: classifications become stale as content and services change. Filter illusion: an interface offers facets that the data cannot populate reliably. Folksonomy as authority: user tags are treated as a governed classification without review.

Product example

Host: Can we see that in a concrete product situation?

Guide: A library can list thousands of reports, but cannot reliably filter by topic, audience, region, or publication status because those attributes were never defined consistently. The interface problem begins long before the filter.
